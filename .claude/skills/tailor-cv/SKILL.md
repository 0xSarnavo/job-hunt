# Tailor CV to a job posting

Input: a job posting URL or pasted description. Output: a tailored CV (HTML + PDF) plus a
keyword-coverage report, in `~/Downloads/cv/tailored/<Company>-<ShortRole>/`.

## Hard rules (before anything else)

1. **Never fabricate.** Every claim must trace to the base CVs' facts. A missing keyword is
   either mapped to a true fact, rephrased into one, or reported as "cannot claim honestly" —
   never invented. The numbers (7,000+ devs, $200K, 1M+ impressions, etc.) are fixed; never
   inflate them.
2. **No "crypto" or "web3" wording** — say "distributed systems" or "blockchain". Company
   names (Avalanche, Chainlink) stay. Verify with grep before rendering.
3. **Industry reads as tech**, role-focused: what was done, not what industry it was in.

## Step 1 — ingest the posting

- URL → fetch it (`tinyfish fetch content get --format markdown "<url>"`, fallback
  `firecrawl scrape`). Text → use as-is.
- Extract: exact job title, seniority, location/remote, must-have skills, nice-to-haves, and
  the **literal keyword phrasings** the posting uses (ATS and recruiters search exact
  strings: "developer marketing" ≠ "marketing to developers"; "PLG" ≠ "product-led growth" —
  when both forms exist, use both, e.g. "Product-Led Growth (PLG)").

## Step 2 — pick the base variant

Bases live in `~/Downloads/cv/Marketing-Roles/` (generated by `build.mjs`) and the
single-variant folders next to it. Map by role family:

| Posting looks like | Base file |
|---|---|
| DevRel / Developer Advocate | `../DevRel-Developer-Advocate/Sarnavo_Saha_Sardar_CV_DevRel.html` |
| Developer Experience / DX | `../Developer-Experience/Sarnavo_Saha_Sardar_CV_DX.html` |
| Product Marketing / PMM | `../Product-Marketing/Sarnavo_Saha_Sardar_CV_PMM.html` |
| Developer Marketing | `Sarnavo_Saha_Sardar_CV_Developer_Marketing.html` |
| Ecosystem / Partner Marketing | `Sarnavo_Saha_Sardar_CV_Ecosystem_Marketing.html` |
| Growth Marketing | `Sarnavo_Saha_Sardar_CV_Growth_Marketing.html` |
| Marketing Ops / GTM Ops / RevOps | `Sarnavo_Saha_Sardar_CV_Marketing_Ops.html` |
| Field / Events / Community programs | `Sarnavo_Saha_Sardar_CV_Field_Events.html` |
| GTM Engineer / outbound / sales eng-ish | `Sarnavo_Saha_Sardar_CV_GTM_Engineer.html` |

Ambiguous posting → pick the family covering the most must-haves; note the runner-up in the
report.

## Step 3 — keyword audit

Build a table: every must-have and nice-to-have keyword → present in base? (exact-string
grep, case-insensitive) → if absent, which true fact can carry it, or "cannot claim".
Coverage % before and after.

## Step 4 — tailor (copy, never edit the base)

Copy the base HTML into the output folder as `Sarnavo_Saha_Sardar_CV_<Company>.html`, then:

- **Tagline**: mirror the posting's exact title phrase when honest (e.g. applying for
  "Developer Marketing Manager" → tagline leads with "Developer Marketing").
- **Summary**: re-weight 2–3 sentences toward the posting's top must-haves, using their
  vocabulary verbatim where true.
- **Bullets**: swap emphasis order so the most relevant bullets lead each role; rephrase to
  the posting's exact terms ("campaigns" → "integrated campaigns" only if the fact supports
  it). Do not add bullets without a source fact.
- **Skills block**: reorder so matched keywords appear early; add acronym+spelled-out pairs.
- **Location line**: if the posting is remote-global, keep "Bengaluru, India"; never remove.
- ATS hygiene is inherited from the template (single column, real text, standard headings,
  no tables/images) — do not add columns, icons, or graphics.

## Step 5 — render + verify

```bash
B="/Applications/Brave Browser.app/Contents/MacOS/Brave Browser"
"$B" --headless --disable-gpu --no-pdf-header-footer \
  --print-to-pdf="<out>.pdf" "file://<out>.html"
grep -icE "crypto|web3" <out>.html   # must be 0
```

Check the PDF is ≤2 pages (`mdls -name kMDItemNumberOfPages -raw`).

## Step 6 — report

Write `keyword-report.md` in the output folder: chosen base + why, the audit table,
coverage before → after, keywords that could NOT be honestly claimed, and any posting
requirements that are genuine gaps (them, not phrasing). Send the PDF and report to the
user (SendUserFile). If invoked by the pipeline, also record the CV path against the job.
